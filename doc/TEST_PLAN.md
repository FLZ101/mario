# Mario OS Test Plan

## 1. Goal

Test Mario at two levels:

1. **Program behavior tests**
   - Run simple programs that read stdin and write stdout.
   - Use the serial console for deterministic text assertions.

2. **Terminal/VGA behavior tests**
   - Run interactive programs such as `vim`.
   - Check the VGA framebuffer using QEMU monitor memory reads and
     `screendump`.

## 2. Console layout after boot

After boot:

| Device | Console type | Purpose |
|---|---|---|
| `/dev/tty1` | VGA foreground | startup screen |
| `/dev/tty2` | VGA | oksh |
| `/dev/tty3` | VGA | oksh |
| `/dev/tty4` | VGA | oksh |
| `/dev/tty5` | VGA | oksh |
| `/dev/tty6` | VGA | oksh |
| `/dev/ttyS0` | Serial | oksh |

F1-F6 switches the foreground VGA console.

## 3. QEMU control channels

One QEMU process can provide:

- `-serial stdio` for the serial shell.
- `-monitor unix:/tmp/mario-monitor.sock,server=on,wait=off` for:
  - `sendkey` to type on VGA
  - `xp` to read VGA text memory
  - `screendump` to capture the framebuffer

## 4. Lit-style serial tests

Use `tests/behavior/lit_shell_test.py`.

Test syntax:

```text
# RUN: echo hello > /root/out.txt
# RUN: cat /root/out.txt
# CHECK: hello
# CHECK-NOT: goodbye
```

This is suitable for simple programs:

- `echo`
- `cat`
- `ls`
- `cp`
- `mv`
- `rm`
- `touch`
- small custom test programs

Example:

```text
# RUN: printf 'hello\n' | cat
# CHECK: hello
```

## 5. Lit-style VGA tests

Use `tests/behavior/vga_lit_test.py`.

Test syntax:

```text
# SERIAL: command
# VGA-CHECK: text
# VGA-CHECK: row,col,text
# VGA-CHECK-NOT: text
# SCREENDUMP: path
```

This is suitable for:

- escape sequences
- cursor movement
- colors/attributes
- screen clearing
- vim-like final screens

## 6. Simple stdin/stdout program strategy

For each program:

1. Start QEMU with `-serial stdio`.
2. Wait for `/ # `.
3. Send command plus piped stdin.
4. Wait for the next prompt.
5. Assert expected stdout text.

Pseudocode:

```python
def test_stdin_stdout(command, stdin_text, expected):
    child.sendline(command)
    child.expect(PROMPT)
    output = child.before + child.after
    assert stdin_text in output
    assert expected in output
```

## 7. Vim and full-screen program strategy

For `vim`:

1. Start QEMU with serial + monitor.
2. Use serial to start a getty on `/dev/tty1` if needed.
3. Wait until VGA text shows a shell prompt.
4. Use monitor `sendkey` to type:

   ```text
   vim /root/test.txt<CR>
   ihello world<ESC>
   :split<CR>
   :set number<CR>
   ```

5. Wait for Vim to render.
6. Dump the screen:

   ```text
   screendump /tmp/vim-final.ppm
   ```

7. Compare against a golden image:

   - text checks: `VGA-CHECK`
   - pixel checks: golden `.ppm` comparison

## 8. VGA text-buffer checks

The VGA text buffer is at `0xb8000`.

Read it with:

```text
xp /4000bx 0xb8000
```

Each cell is two bytes:

- even byte: character
- odd byte: attribute/color

This allows exact checks:

```text
# VGA-CHECK: 3,5,C
```

## 9. Golden screenshot generation

For visual-only features:

```sh
python3 tests/behavior/vga_test_generator.py
```

For vim:

```sh
python3 tests/behavior/vga_vim_golden.py tests/behavior/vga_seqs/vim.vim
```

Generated images live in:

```text
tests/behavior/vga_expected/
```

## 11. CI/regression workflow

Run in order:

```sh
make kernel
make -C qemu tmp/kernel.exe tmp/rdx

python3 tests/behavior/lit_shell_test.py
python3 tests/behavior/vga_lit_test.py

python3 tests/behavior/vga_test_generator.py --check
python3 tests/behavior/vga_vim_golden.py tests/behavior/vga_seqs/vim.vim
```

## 12. Rules of thumb

- Use serial tests for stdin/stdout behavior.
- Use VGA text-buffer checks for text position/cursor behavior.
- Use `screendump` for colors, cursor visibility, and vim final layout.
- Keep golden images small and generated by a script.
- Never use `sleep` alone when a prompt/text marker can be waited for.
